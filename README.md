# DM CRM

Ticket and issue management for a Ghanaian customer-service and Debt Management (DM) team. Agents log client contacts from calls, WhatsApp, SMS and walk-ins; supervisors assign them to DM officers; officers work their queue from their phones; managers track SLAs, payments and performance across all 16 regions.

Built with **React 19, Vite 7, TypeScript, Tailwind CSS v4 and Supabase** (Postgres, Auth, Row Level Security, Realtime, Storage, Edge Functions).

## Features

**Tickets**
- Ticket numbers generated by the database: `TKT-2026-000123`.
- Multi-section creation form with client lookup by ID or phone, duplicate warning for active tickets of the same issue type, an autosaved draft on the device, and "Save & create another".
- Due date = DATE OPENED + the issue type's SLA days (configurable). Only supervisors and admins can override it; DATE OPENED can only be changed by admins.
- Payment fields (PAYMENT, PAYMENT SOURCE, TYPE, STATUS) are required for PAYMENT ISSUE, PAYMENT ASSIST and UNREFLECTED PAYMENTS. Configurable per issue type.
- Ghana phone validation (`0XXXXXXXXX` / `+233XXXXXXXXX`) with one-tap Call and WhatsApp buttons.
- Status workflow Open → In-Progress → Resolved → Closed, with reopen (supervisor/admin) and a mandatory REASON FOR OPEN STATUS on overdue tickets.
- Comments, file attachments (private storage, 10 MB), full change history and a printable ticket view.

**Assignment and notifications**
- Single and bulk assignment with a workload-aware officer picker (open / in-progress / overdue counts) and an automatic suggestion that prefers officers in the client's region.
- In-app notification bell, updated in real time, plus toasts for new assignments.

**My Tickets (DM officers)**
- Landing page with summary cards, tabs (active, open, in progress, overdue, resolved), colour-coded due badges, quick "Start work", and a side drawer to update and resolve without leaving the list.

**All Tickets**
- Server-side pagination, sorting and filtering (status, region, issue type, contact type, officer, payment fields, priority, community, date opened and due date ranges, overdue).
- Filters live in the URL (shareable), saved views per user, column chooser, bulk assign and bulk status change.
- Export to Excel, CSV and PDF; import from Excel/CSV with row-by-row validation and a downloadable template.

**Dashboard**
- Global filters (date range, region, officer, issue type, contact type).
- 10 KPI cards, trend chart, status donut, contact type / issue type / community / officer workload charts, clickable region tiles and recent activity. Every card and bar drills down to the matching ticket list.

**Reports**
- Status per region, issue type per region, payments per region (by type, source, status), officer performance per contact type, SLA / overdue ageing (0–2, 3–7, 8–14, 15+ days), and a printable monthly report. Excel and PDF export for each.

**Administration**
- Users (invite by email or temporary password, roles, regions, activate/deactivate, link to officer record), officers, all dropdown values (add, rename, reorder, deactivate), SLA settings and a searchable audit log.

**Experience**
- Collapsible sidebar, dark mode, responsive down to phones, command palette (`Ctrl/⌘ + K`), shortcuts (`N` new ticket, `/` search), skeleton loaders, empty states, error boundaries, confirmation dialogs, keyboard and screen-reader friendly controls.
- Money shown as `GH₵ 1,250.00`, dates as `DD/MM/YYYY`, business times in `Africa/Accra`.

## 1. Create and configure Supabase

1. Create a project at [supabase.com](https://supabase.com). Choose a region close to Ghana (e.g. `eu-west`).
2. Note the **Project URL**, **anon public key** and **service_role key** under *Project Settings → API*.

### 2. Apply the database schema and seed data

**Option A — Supabase CLI (recommended)**

```bash
supabase login
supabase link --project-ref <your-project-ref>
supabase db push                      # runs supabase/migrations/*.sql in order
psql "<your-connection-string>" -f supabase/seed.sql   # or paste seed.sql into the SQL editor
```

**Option B — SQL editor only**

Open *SQL Editor* in the dashboard and run each file in this order, then the seed:

```
supabase/migrations/20260101000001_extensions_enums_lookups.sql
supabase/migrations/20260101000002_profiles_officers.sql
supabase/migrations/20260101000003_tickets.sql
supabase/migrations/20260101000004_ticket_triggers.sql
supabase/migrations/20260101000005_reporting.sql
supabase/migrations/20260101000006_rls.sql
supabase/migrations/20260101000007_storage_realtime.sql
supabase/seed.sql
```

The seed inserts all dropdown values (5 contact types, 7 issue types with SLAs, 2 payment sources, 10 payment types, 3 payment statuses, 16 regions), the 6 DM officers (GLORIA, JENNIFER TWUM-BARIMAH, REJOICE KLUTSE, VIVA, ESTHER, CHARITY) and about 150 realistic tickets spread over the last six months with history. It is safe to re-run; tickets are only generated if the table is empty.

**Local development with Docker** (optional): `supabase start` then `supabase db reset` applies migrations and `seed.sql` automatically.

### Auth settings

*Authentication → URL Configuration*:
- **Site URL**: your app URL (e.g. `https://crm.example.com`, or `http://localhost:5173` in development).
- **Redirect URLs**: add `https://crm.example.com/reset-password` and `http://localhost:5173/reset-password`.

*Authentication → Providers → Email*: keep email enabled. Consider disabling **"Allow new users to sign up"** so accounts are only created by admins.

For production, configure custom SMTP (*Authentication → SMTP*) so invitation and reset emails are delivered reliably.

### Deploy the `invite-user` Edge Function

The admin "Add user" dialog calls an Edge Function that uses the service role key on the server (never in the browser).

```bash
supabase functions deploy invite-user
```

`SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are provided automatically to hosted Edge Functions. If you self-host, set them with:

```bash
supabase secrets set SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
```

The function checks that the caller is an active admin, then either sends an invitation email or creates the user with a temporary password, sets the role and region, and optionally links the officer record.

### 3. Create the first admin

1. In the dashboard go to *Authentication → Users → Add user → Create new user*, enter your email and a password and tick **Auto Confirm User**.
2. A profile row is created automatically with the role `agent`. Promote it in the SQL editor:

```sql
update public.profiles
set role = 'admin', full_name = 'Your Name'
where email = 'you@example.com';
```

3. Sign in to the app. From now on, add everyone else from **Administration → Users**.

To give a DM officer a login, invite them with the role **DM Officer** and pick their officer record (e.g. GLORIA) in "Link to officer record". Tickets assigned to that officer then appear on their My Tickets page.

## 4. Run the app locally

```bash
cp .env.example .env.local
# edit .env.local:
#   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
#   VITE_SUPABASE_ANON_KEY=<anon public key>

npm install
npm run dev          # http://localhost:5173
```

Other scripts:

| Command | Purpose |
| --- | --- |
| `npm run build` | Production build into `dist/` |
| `npm run build:strict` | Type-check, then build |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run preview` | Serve the production build locally |
| `npm run lint` | ESLint |
| `npm run format` | Prettier (with Tailwind class sorting) |

Only the **anon** key goes in the frontend. Security is enforced by Row Level Security in the database, so the anon key is safe to ship.

## Deployment

The app is a static single-page app. Any static host works; configs for two are included.

**Netlify** — `netlify.toml` is included (build `npm run build`, publish `dist`, SPA fallback). Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` under *Site settings → Environment variables*.

**Vercel** — `vercel.json` provides the SPA rewrite. Framework preset *Vite*; add the same two environment variables.

**Other hosts** (Cloudflare Pages, S3, Nginx): serve `dist/` and rewrite all unknown paths to `/index.html`.

After deploying, add the production URL and `/reset-password` to Supabase Auth redirect URLs.

## Roles and permissions

Every rule below is enforced in Postgres (RLS policies and triggers), not just hidden in the UI.

| Capability | Admin | Supervisor | Agent | DM Officer |
| --- | :-: | :-: | :-: | :-: |
| See tickets | All | All | Ones they created | Assigned to them |
| Create tickets | ✓ | ✓ | ✓ | – |
| Edit client / issue details | ✓ | ✓ | Own tickets | – |
| Change DATE OPENED | ✓ | – | – | – |
| Override DUE DATE | ✓ | ✓ | – | – |
| Assign / reassign | ✓ | ✓ | Own tickets | – |
| Update status, REMARKS, COMPLETION DATE, payment fields | ✓ | ✓ | – | Assigned tickets |
| Close / reopen | ✓ | ✓ | – | – |
| Delete tickets | ✓ | – | – | – |
| Import / export | ✓ | ✓ | ✓ (own) | – |
| Dashboard | ✓ | ✓ | ✓ (own) | – |
| Reports | ✓ | ✓ | – | – |
| Administration | ✓ | – | – | – |

After sign-in, DM Officers land on **My Tickets**; everyone else lands on the **Dashboard**. Deactivated users are signed out and blocked by RLS.

Role guides for end users are in [`docs/`](docs):
[Agent](docs/agent-guide.md) · [DM Officer](docs/dm-officer-guide.md) · [Supervisor](docs/supervisor-guide.md) · [Admin](docs/admin-guide.md)

## How the data model works

- **Lookups by name.** Tickets store dropdown values as text with foreign keys to the lookup tables (`ON UPDATE CASCADE`). Renaming a value in Administration updates every ticket instantly; values in use cannot be deleted, only deactivated.
- **Triggers do the bookkeeping.** `tickets_before_insert/update` generate ticket numbers, normalise phone numbers, compute due dates, enforce field-level permissions per role and valid status transitions, stamp `assigned_at / resolved_at / closed_at`, and handle reopening. `tickets_after_change` writes the audit trail (`ticket_activity`) and creates notifications.
- **Reports run in the database.** Dashboard and report numbers come from SQL functions declared `SECURITY INVOKER`, so they automatically respect RLS: an agent's dashboard only counts their own tickets. Date filters apply to DATE OPENED in Africa/Accra time.
- **Realtime.** `tickets`, `notifications`, `ticket_comments` and `ticket_activity` are in the `supabase_realtime` publication; the app refreshes lists and counters as changes arrive.
- **Attachments.** Stored in the private `ticket-attachments` bucket under `<ticket_id>/…`; access follows ticket visibility and files are served through short-lived signed URLs.
- **Overdue.** A ticket is overdue when its DUE DATE is before today (Accra time) and its status is Open or In-Progress.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Yellow "Supabase is not configured" banner on login | `.env.local` is missing or the dev server was started before creating it. Restart `npm run dev`. |
| Login works but the app shows a spinner forever / signs out | The user has no row in `profiles` (created before migrations ran). Insert one: `insert into profiles (id, email, full_name) select id, email, email from auth.users where email = '…';` |
| "Your account isn't linked to an officer yet" | Administration → Users → edit the user → choose *Linked officer*. |
| "Add user" fails with *Failed to send a request to the Edge Function* | Deploy `invite-user` (see above) and check *Edge Functions → Logs*. |
| Invitation or reset emails don't arrive | Configure custom SMTP; the built-in sender is heavily rate-limited. Check the redirect URLs. |
| "permission denied" / "new row violates row-level security" | Working as designed: the action isn't allowed for that role. Check the permission table above. |
| Dashboard numbers look lower than expected | Check the date range (defaults to *This month*) and remember agents only see their own tickets. |
| Realtime updates don't appear | Ensure migration `…000007` ran (it adds tables to `supabase_realtime`) and that Realtime is enabled for the project. |
| Import says OFFICER not found | Officer names must match exactly (case-insensitive) — download the template for the current list. |
| Excel dropped leading zeros from phone numbers | The importer restores them automatically for 9-digit values. |
| `npm install` fails with `EALLOWREMOTE` | Newer npm blocks tarball-URL dependencies. The included `.npmrc` sets `allow-remote=root` (needed for SheetJS from `cdn.sheetjs.com`). If your npm ignores it, run `npm i --allow-remote=root`. |
| `npm install` fails on `xlsx` behind a proxy | SheetJS is installed from `cdn.sheetjs.com` (the npm registry version is outdated). Allow that host through your proxy. |
